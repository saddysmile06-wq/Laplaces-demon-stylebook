# Автокоммит и push (правила только для этого репозитория)

**Автор репозитория разрешил:** агент сам коммитит свою работу и периодически пушит. Правило корневого `C:\Obsidian-Data\CLAUDE.md` «коммитит только пользователь» **здесь не действует**. Вне папки `laplace-mascot` оно остаётся в силе.

Всё делается через `tools/autocommit.py`, руками `git commit` / `git push` без него не пиши. Скрипт сам проверяет всё, что ниже.

## Когда коммитить
Коммитим **законченные куски работы**, а не «каждую секунду»:
- добавлен или обновлён арт / клип (+ его `index.json` / `clip.json`);
- изменена документация или инструкция;
- правка инструментов (`tools/`, `pipeline/`);
- закончен шаг многошаговой задачи.

Страховка по таймеру: если есть изменения и с прошлого коммита прошло **15 минут**, закоммить то, что есть, если оно проходит `validate`. Не коммить на полпути сломанное состояние.

Команда: `python tools/autocommit.py commit -m "тип(область): описание"`. Дальше можно `tick` (см. ниже).

## Сообщение коммита
`тип(область): что сделано`, по-русски, до ~70 символов, в прошедшем времени, без точки.

| Тип | Когда |
|---|---|
| `art` | арты, спрайты, референсы |
| `anim` | клипы и анимации |
| `canon` | `canon/*` (отдельным коммитом, см. запреты) |
| `style` | стайлбук |
| `ai` | инструкции, шаблоны, `AGENTS.md` |
| `tools` | `tools/`, `pipeline/` |
| `docs` | README, CHANGELOG |
| `chore` | прочее (`.gitignore`, мелочи) |
| `fix` | исправление ошибки |

Примеры: `art(from-regina): добавил 12 референсов`, `anim(clips): клип idle-v1, 96 кадров`, `tools(setup): починил определение LFS`. Скрипт сам добавляет подпись `Co-Authored-By: <агент>`.

Одна тема на коммит. Не мешай арты и правки скриптов в одном.

## Когда пушить («пушить легко»)
Push делает `python tools/autocommit.py push` (или `tick`). Он отправляет, когда выполнено **любое** из:
- накопилось **5 коммитов**;
- с последнего push прошло **30 минут**;
- конец сессии или явная просьба автора (`--now`).

Правила лёгкого push:
- Перед отправкой скрипт делает `git pull --rebase --autostash`. Конфликт: он откатывает rebase, **ничего не отправляет** и сообщает; ты не разруливаешь чужие правки сам.
- Никакого `--force`, `reset --hard`, `commit --amend` на отправленном, переписывания истории.
- Порциями: не копи гигабайты. Если за раз накопилось много картинок, пушь после каждой логической группы, а не одной кучей (квота LFS на GitHub free: 1 ГБ хранилища, 1 ГБ трафика в месяц).
- Каждая новая версия большого `.aseprite` занимает место в LFS целиком: правь такие файлы реже, коммить итог, а не промежуточные сохранения.
- После push напиши одну строку: что отправлено и сколько коммитов.

## Чего скрипт не даст сделать
- работать не на ветке `main` (настройка `branch`);
- коммитить при идущих merge/rebase;
- коммитить, если `validate.py` или `build.py` упали;
- коммитить файлы из `blocked_paths` (`.env`, `.venv/`, `frames/`, `Tg-data/`, логи) и **файлы больше 50 МБ** без вопроса автору;
- коммитить, если в добавленных строках похоже на секрет (ключи, токены, приватные ключи): всё откатывается из индекса;
- смешивать `canon/` с другими изменениями: `canon/*` коммитится только отдельным коммитом `canon(...)` и **только если автор сам просил поменять канон**;
- пушить, пока в `tools/autocommit.json` `first_push_confirmed` равно `false` или нет remote.

## Первый коммит
Первый коммит репозитория (импорт всего накопленного) может включать `canon/`: проверка «`canon/` отдельным коммитом» действует только когда в репозитории уже есть история.

## Первый push: ручной ключ автора
Папка `assets/from-regina/` содержит материалы из личной переписки. Пока автор не поставил `"first_push_confirmed": true`, push запрещён, а коммиты локальные. Перед первым публичным push напомни автору один раз: подтвердить это и создать remote (`git remote add origin <URL>`).

## Как это запускать
- **Вручную агентом:** после значимого шага `commit` (хук Stop подстрахует по таймеру).
- **`tick`** сам решает, пора ли коммитить (15 мин) и пушить (5 коммитов / 30 мин): `python tools/autocommit.py tick`. Сообщение можно не задавать, но тогда оно общее («автокоммит, N файлов»); лучше задай `-m`.
- **Диагностика:** `python tools/autocommit.py status`.
- **Claude Code: хук Stop включён** (`.claude/settings.json`). В конце каждого ответа Claude Code сам запускает `python tools/autocommit.py tick`: коммит по таймеру (15 мин), push по таймеру/пачке, пока `first_push_confirmed=false` push тихо пропускается. Хук работает только когда сессия открыта в папке `laplace-mascot`. Отключить лично себе: в `.claude/settings.local.json` напиши `{"disableAllHooks": true}`; отключить всем: убери блок из `.claude/settings.json` или создай `.autocommit-off`. Codex хуков не имеет: там следуй этому документу руками.

## Выключатель
- Файл `.autocommit-off` в корне (он в `.gitignore`) или `"enabled": false` в `tools/autocommit.json` = автокоммит и автопуш выключены.
- Если автор пишет «стоп автокоммит» или «не коммить», создай `.autocommit-off` и больше не коммить, пока не скажут.

## Чего агент не делает даже в автокоммите
- не пушит в чужие репозитории и другие ветки, не создаёт теги и релизы;
- не меняет `tools/autocommit.json` (кроме просьбы автора) и не включает `first_push_confirmed` сам;
- не удаляет файлы автора ради «чистоты коммита»;
- не коммитит в репозитории вне `laplace-mascot`.
